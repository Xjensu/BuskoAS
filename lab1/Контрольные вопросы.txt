1.Чем отличаются друг от друга рабочий каталог (working directory),
  индекс (staging area) и репозиторий (.git directory)?
Ответ:
  Рабочий каталог (working directory) - файлы проекта, с которыми мы работаем.
  Индекс (staging area) - подготовленные к следующему коммиту изменения.
  Репозиторий (.git) - база данных Git с коммитами, ветками и историей проекта.

2.Какие состояния может принимать файл в Git и какими командами осуществляются переходы между ними?
Ответ:
  Файл может быть:
    неотслеживаемым - git add добавляет его в индекс;
    отслеживаемым, изменённым - git add переносит изменения в индекс;
    подготовленным - git commit сохраняет его в репозитории;
    неизменённым - после коммита;
    удалённым - git rm удаляет файл и добавляет это изменение в индекс.
  Отменить подготовку можно командой git restore --staged <файл>.

3.Почему информация об авторе коммита (user.name, user.email) не должна изменяться после того,
  как коммит опубликован в общем репозитории?
Ответ:
  После публикации коммита изменение user.name или user.email нарушает соответствие между коммитом
  и его автором. Это может привести к путанице, проблемам с авторством и 
  необходимости переписывать историю репозитория.

4.В чем разница между настройками Git на уровне local и --global?
  Почему в данной работе используется local-уровень?
Ответ:
  local действует только в текущем репозитории и хранится в .git/config.
  --global применяется ко всем репозиториям пользователя.
  В данной работе используется local, чтобы настройки автора не влияли на другие проекты.
