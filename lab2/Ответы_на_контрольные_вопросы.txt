ЛАБОРАТОРНАЯ РАБОТА № 2
ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

1. Чем отличаются git fetch, git pull и git push?

git fetch получает новые объекты и обновляет удаленно-отслеживаемые ссылки, не изменяя текущую ветку; git pull после получения интегрирует изменения в текущую ветку; git push отправляет локальные коммиты и обновляет ссылки удаленного репозитория.

2. Почему создание ветки в Git является дешевой операцией?

Ветка представляет собой ссылку на существующий коммит. Для ее создания не требуется копировать файлы или снимки проекта.

3. Что происходит при разных изменениях одного участка файла?

Git пытается объединить изменения автоматически; при несовместимых правках фиксирует конфликт и добавляет маркеры. Итоговую версию файла должен определить разработчик.

4. Для чего конфликт создается намеренно?

Чтобы изучить воспроизводимый сценарий конфликта, чтение маркеров и процесс ручного разрешения, а не зависеть от случайного совпадения изменений.

5. Чем аутентификация по SSH-ключу предпочтительнее пароля?

При аутентификации по SSH приватный ключ остается у разработчика; сервер проверяет доказательство владения ключом по открытому ключу. Доступ можно отозвать удалением публичного ключа, не передавая пароль учетной записи.

6. Что показывает второй родитель merge-коммита?

Второй родитель указывает на вершину истории присоединяемой ветки в момент слияния. Первый родитель обычно соответствует целевой ветке до merge.
